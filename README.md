# muse-stage

発表で、ミューズと一緒に登壇するための、出力専用の相方アプリです。
VRM のキャラクターを大きく表示し、ミューズの返事を読み上げながら口を動かします。スライドもこのアプリ自身に敷けます。

- 作業の指示書は、このリポジトリの `AGENTS.md`（担当はミューズ。舞台用チャット向けの指示書は `INSTRUCTIONS_*.md`）
- GitHub: oosawak/muse-stage-prototype（実行用の置き場所は Mac の ~/Workspace の下）
- Web版（CC0モデル・ブラウザ読み上げ）: https://oosawak.github.io/materials/muse-stage/ （このリポジトリの `docs/` にも同じビルドが入っていて、GitHub Pages で公開できます）

## 起動

ビルド済みのアプリ:

```
open "src-tauri/target/release/bundle/macos/Muse Stage.app"
```

作り直すとき（Node と Rust が要る）:

```
npm install
npx tauri build --bundles app   # アプリを作る
npx tauri dev                   # 開発用に起動（画面の変更がすぐ反映される）
```

## 使い方

基本は **直送** です。舞台用チャットのミューズが、返事のたびに同じ文を Mac の `~/muse-stage-inbox.md` に書きます。舞台アプリは 0.7 秒ごとに見張っていて、新しい返事が届くと自動で読み上げます（パネルの「新しい返事を自動で読む」、初期はオン）。

手で入れることもできます。返事をコピーして左下パネルの欄に貼り、「読み上げ」（またはスペースキー、欄の中なら ⌘Enter）を押すと、その文を読み上げます。字幕も出ます。

### 他の AI でも使えます

舞台が受け取るのは「文」だけなので、**文を作る AI は問いません**。届け方はどれも AI の種類に依存しません。

- 直送ファイル： `~/muse-stage-inbox.md` に決まった形式で書けるエージェント（Codex、Claude Code など）なら、そのまま届けられます
- ウェブフック： ローカルの受け口（`http://127.0.0.1:17654/reply`）へ POST できれば届きます
- MQTT 中継： Web版へは公開中継経由で届けられます（下の「Web版と中継の合言葉」）
- 貼り付け： どの AI の文でも、欄に貼れば読み上げます

ミューズ専用なのは、Muse.app の画面を読む AX取り込みだけです。

- 全画面：「全画面」ボタンか F キー。止める：Esc
- 左下の操作パネルは、ふだんは薄く、マウスを動かすと濃くなる。「パネルをたたむ」で下に畳めます。H キーでパネルごと隠せます
- スライド：「スライドを選ぶ」で画像・PDF・動画を選ぶと舞台の後ろに敷けます（PDF は全ページが1枚ずつになります）。送りは →／← キー、舞台のクリック、パネルの ◀▶
- キャラクターをクリックすると、脇へ歩いてよけます。もう一度クリックで戻ります

### 読み上げのしくみ（パネルの選択）

- **VOICEVOX（アプリ版の初期）**：ローカルの VOICEVOX（127.0.0.1:50021）で読みます。ずんだもんの声はこの経路です
- 自動：WebView の speechSynthesis を使い、1.5 秒たっても始まらなければ macOS の `say` に切り替える
- WebView の speechSynthesis だけ／macOS の say だけ、にも切り替えられる。say の声は Kyoko が初期
- Web版では、ブラウザ内蔵の読み上げ（speechSynthesis）になります（https のページからはローカルの VOICEVOX に繋げないため）

### 声分け（二人で発表するとき）

パネルの「声分け（本人＝男性の声）」をオンにすると、文中の印で話者を分けられます。

- 行単独の `@user` の下は本人の文として、VOICEVOX の男性話者（玄野武宏）で読む
- 行単独の `@muse` の下はミューズの文として、ずんだもんで読む。印が無い文はミューズ扱い
- 字幕には「本人：」「ミューズ：」の見出しが付きます
- **本人の文を読んでいる間、キャラクターは喋りません**（口パクとおしゃべりの動きを止めて、聞く側に回ります）

### Muse.app から AX で取り込む（実験・第2段）

「AX取り込み」で、Muse.app の画面の文字をアクセシビリティ経由で読み、いちばん新しい返事を欄に入れます。取り込んだ返事は右上の一覧に出て、選んで読み直せます（一覧は「たたむ」で折りたためます）。
「AX自動取り込み」を付けると、2 秒ごとに見て、新しい返事が出たら読み上げます。直送の「新しい返事を自動で読む」とは別のスイッチです。

使うには、システム設定 → プライバシーとセキュリティ → アクセシビリティ で「Muse Stage」を許可してください（未許可のままでは読めません）。エラー文で osascript が名指しされる場合は、`/usr/bin/osascript` も同じ一覧に追加して許可してください。

読み取り方式についての実機知見（2026-11-14）: Muse.app では `entire contents` が常に 0 件を返すため、子要素（UI elements）をレベルごとにたどる幅優先で AXStaticText を集めています。会話メッセージには2つの姿があります。古いものは「ユーザーメッセージ: 」「アシスタントメッセージ: 」の接頭辞つきで1要素に全文が入りますが、新しいものは段落・コード片ごとにバラバラの要素に分かれ、接頭辞がありません（ユーザーの発言だけ先頭に「自分:」の断片が付きます）。そのため要素の経路も一緒に集め、会話リストの子ごとに断片を組み立て直しています。接頭辞だけを探すと最新の返事を逃します。また、画面に見えている範囲しかツリーに載らないため、取り込み前に Muse.app で一番下までスクロールしておくと新しい返事が載ります。幅優先の走査には時間がかかるため、取り込みには十数秒かかることがあります。

## Web版と「中継の合言葉」

Web版（ブラウザで開く版）は、アプリ版と違ってミューズからのファイルを直接受け取れないので、返事は公開MQTT中継で届きます。そのとき「どの舞台に届けるか」を決めるのが、**中継の合言葉**です。設定は、使う人が自分で行います。

1. **合言葉は、使う人が自分で適当な文字列を作ります**（他人と被らない、長めの文字列がおすすめです）
2. **舞台のパネルで設定します**：「Web直送（MQTT中継）」にチェックを入れ、その下の「中継の合言葉」の欄に、その文字列を入れます（アプリ版・Web版とも同じ欄です）
3. **ミューズ側では、同じ文字列を決まったファイルに置きます**：`~/workspace/stage-relay-topic.txt`。送信スクリプト（`tools/send_reply_mqtt.mjs`）は、そこから合言葉を読みます
4. **ミューズへの指示書には、合言葉そのものは書きません**。「合言葉はそのファイルから読む」という決めだけを書きます。合言葉の値は、チャットやこのリポジトリには出さないでください
5. **文が届くのは、同じ合言葉を設定した同士だけです**。合言葉が違う舞台には届きません

### Web版の同梱スライド（デモ用）

Web版の置き場所に `slides/manifest.json` があると、開いた時点でそのスライドが読み込まれます（アプリ版には影響しません）。形式:

```json
{
  "title": "資料の名前",
  "slides": ["slides/pitch/slide-01.png", { "src": "slides/movie.mp4", "type": "video" }],
  "links": { "11": [{ "x": 0.055, "y": 0.375, "w": 0.89, "h": 0.125, "url": "https://example.com/", "label": "表示名" }] }
}
```

- `slides`: 画像はURLの文字列。動画（MP4など）は `{ "src": ..., "type": "video" }` と書くと、スライドの1枚として再生できます。`{ "type": "games", "games": [{ "label": "表示名", "src": "ゲームのURL" }] }` と書くと、タブで切り替えてその場で遊べるゲームスライドになります。`{ "src": "ページのURL", "type": "iframe" }` と書くと、Webページそのものを1枚として埋め込みます（ページ内のリンクもそのまま効きます）
- `links`（任意）: ページ番号ごとに、画像の割合（x・y・w・h）で指定した透明なリンク領域を重ねます
- アプリ版・Web版とも、「スライドを選ぶ」で動画ファイルを選んでも動画スライドになります
